# Профиль, авторизация и рейтинг

## Что работает офлайн

- Каждый запуск создаёт постоянный гостевой идентификатор устройства.
- Партии, победы, ничьи, поражения, задачи и попытки сохраняются локально.
- Локальный шахматный рейтинг изменяется по Elo относительно выбранного уровня компьютера.
- Рейтинг тактики изменяется после первого решения задачи с учётом рейтинга задачи.
- Гостевые показатели не публикуются в общем рейтинге и не синхронизируются между устройствами.

## Целевая серверная модель

Сервер является единственным источником истины для online-рейтинга. Мобильное и веб-приложение используют один `player_id`, а внешние аккаунты только подтверждают личность пользователя.

```text
player
  id, display_name, created_at
external_identity
  player_id, provider(yandex|vk), provider_user_id
rating
  player_id, pool(rapid|blitz|puzzles), value, deviation, games
game_result
  id, white_id, black_id, result, moves, finished_at
puzzle_result
  player_id, puzzle_id, solved, attempts, finished_at
```

Минимальные API-контракты:

- `POST /v1/auth/yandex/exchange` и `POST /v1/auth/vk/exchange` — обмен одноразового authorization code;
- `GET /v1/profile` — профиль, рейтинги и агрегированная статистика;
- `POST /v1/profile/claim-guest-progress` — однократный перенос локального прогресса после входа;
- `POST /v1/games/{id}/result` — серверно проверенный результат партии;
- `POST /v1/puzzles/{id}/result` — результат и число попыток;
- `GET /v1/leaderboards/{pool}` — таблица лидеров.

Токены провайдеров не должны становиться идентификаторами Velvet и не должны попадать в Git. Мобильный клиент использует Authorization Code + PKCE, передаёт code серверу, а сервер создаёт собственную короткую access-сессию и rotating refresh token.

## Что требуется для включения кнопок входа

1. Зарегистрировать приложения в кабинетах Яндекс OAuth и VK ID.
2. Утвердить Redirect URI для Android, iOS и веб-версии.
3. Развернуть HTTPS API и базу профилей.
4. Добавить client/app ID в платформенную конфигурацию; секреты оставить только на сервере.
5. Обновить политику конфиденциальности: перечислить получаемые поля профиля, сроки хранения и процедуру удаления аккаунта.
6. Проверить связывание двух провайдеров с одним профилем и защиту от повторного переноса гостевого прогресса.

Код уже содержит общие модели `PlayerProfile`, `ProfileSnapshot`, `RatingEntry` и интерфейс `IPlayerAccountService`, поэтому подключение backend не потребует менять игровые экраны или локальное хранилище.
