# Онлайн-режим: архитектурный план

Клиент уже отделён от транспорта контрактом `IOnlineMatchService`. Для полноценного онлайна нужен отдельный сервер — его нельзя безопасно имитировать внутри мобильного приложения.

## Этапы

1. ASP.NET Core Account API: профили, OAuth, JWT/rotating refresh tokens и хранилище — основа реализована; перед production остаются PostgreSQL и deployment.
2. Матчмейкинг: очереди по контролю времени и диапазону рейтинга.
3. SignalR: события матча, реконнект, серверные шахматные часы.
4. Авторитетный сервер: каждый ход повторно проверяется шахматным ядром.
5. PostgreSQL: пользователи, партии, рейтинги, жалобы; Redis: очереди и активные матчи.
6. Защита: rate limits, idempotency, журнал событий, базовая античит-аналитика.
7. Наблюдаемость и нагрузочные тесты, затем закрытая бета.

Протокол должен передавать UCI-ходы и FEN-снимки. Клиент никогда не определяет итог партии единолично.
